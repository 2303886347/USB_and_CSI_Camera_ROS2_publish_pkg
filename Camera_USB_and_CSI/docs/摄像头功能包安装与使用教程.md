# Camera_USB_and_CSI 安装与使用教程

## 1. 产物和功能

源码目录：

```text
/home/ubuntu/ros2_ws/src/Camera_USB_and_CSI
```

ROS 2 包名遵循命名规范，使用小写：

```text
camera_usb_and_csi
```

功能包括：

- Jetson CSI 相机节点，通过 `nvarguscamerasrc` 获取图像。
- V4L2 USB 相机节点，默认通过 `/dev/usb_cam` 获取图像。
- 一个 launch 文件，通过 `camera_type:=CSI` 或 `camera_type:=USB` 选择节点。
- CSI 和 USB 节点都默认发布 `/image_raw`，可直接连接 `collect_picture`。
- USB 设备序列号绑定脚本及 udev 规则。

不要同时启动 CSI 和 USB 节点向同一个 `/image_raw` 发布，否则订阅端会收到两个发布者的图像。

### 新终端必须重新加载 ROS 2 环境

`source` 只对当前终端有效。每次新开终端、标签页或 SSH 会话，都要重新执行：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
```

## 2. 设备与绑定参数

部署前必须按第 4 节列出并人工确认 CSI、USB 设备。下表是本功能包验证所使用的设备
映射；实际 `/dev/videoN` 编号应以目标主机的检查结果为准。

| 设备 | 识别结果 |
| --- | --- |
| `/dev/video0` | IMX219 CSI 相机，由 Jetson Argus 使用。 |
| `/dev/video1` | icSpring USB 摄像头的视频采集接口。 |
| `/dev/video2` | 同一 USB 摄像头的非采集接口，不应绑定。 |

USB 摄像头的稳定属性：

```text
VID=32e6
PID=9251
SERIAL=202404150001
V4L2 index=0
```

## 3. 单独验证 CSI 相机

测试脚本使用 Ubuntu 提供且支持 GStreamer 的 OpenCV，确保能够打开 Jetson CSI 管线。

无界面读取 30 帧：

```bash
python3 /home/ubuntu/Desktop/csi_camera_test.py --no-display --frames 30
```

打开测试窗口，按 `q` 或 `Esc` 退出：

```bash
python3 /home/ubuntu/Desktop/csi_camera_test.py
```

CSI 默认使用 `1280x720` 的传感器采集模式，并将 ROS 话题输出缩放为 `640x480`：

```text
sensor-id=0
capture: 1280x720
output: 640x480
60 FPS
```

## 4. 绑定 USB 摄像头为 `/dev/usb_cam`

不要根据设备编号直接猜测 USB 摄像头。`/dev/videoN` 编号可能因插拔顺序或重启发生变化，绑定前必须先手动列出设备并确认画面来源。

### 4.1 列出并人工确认设备

先查看所有视频设备：

```bash
ls -l /dev/video*
```

再使用绑定脚本的只读列表功能：

```bash
bash /home/ubuntu/ros2_ws/src/Camera_USB_and_CSI/scripts/install_usb_camera_rule.sh --list
```

列表中应选择同时满足以下条件的设备：

- `BUS` 是 `usb`。
- `CAPTURE` 是 `yes`。
- `PRODUCT`、`SERIAL` 与准备绑定的 USB 摄像头一致。
- 同一个 USB 摄像头有多个 `/dev/videoN` 时，选择实际能输出画面的 capture 接口。

参考识别结果：

```text
/dev/video0  platform  CSI IMX219
/dev/video1  usb       CAPTURE=yes  应绑定
/dev/video2  usb       CAPTURE=no   不应绑定
```

还应实际打开候选设备确认画面。例如测试 `/dev/video1`：

```bash
gst-launch-1.0 v4l2src device=/dev/video1 \
  ! videoconvert \
  ! autovideosink
```

确认画面来自目标 USB 摄像头后按 `Ctrl+C` 退出。也可以在 `/home/ubuntu/Desktop/usb_camera_test.py` 中把 `cv2.VideoCapture(...)` 的编号改成候选设备编号后运行测试。

### 4.2 修改 `--device` 参数并预览规则

把下面命令中的 `/dev/video1` 改成上一步人工确认的实际设备号。先使用 `--dry-run` 预览规则，此时不会修改系统：

```bash
bash /home/ubuntu/ros2_ws/src/Camera_USB_and_CSI/scripts/install_usb_camera_rule.sh \
  --device /dev/video1 \
  --dry-run
```

如果不传 `--device`，脚本只会显示设备列表并停止，不会自动选择或安装规则。

### 4.3 执行绑定

再次确认脚本输出的设备、VID、PID、序列号和接口 index 正确，然后使用同一个设备参数执行绑定：

```bash
bash /home/ubuntu/ros2_ws/src/Camera_USB_and_CSI/scripts/install_usb_camera_rule.sh \
  --device /dev/video1
```

该命令会在写入 `/etc/udev/rules.d` 时请求一次当前用户的 sudo 密码。

脚本会安装：

```text
/etc/udev/rules.d/99-usb-camera.rules
```

并生成：

```text
/dev/usb_cam -> /dev/video1
```

检查结果：

```bash
ls -l /dev/usb_cam
udevadm info --query=property --name=/dev/usb_cam
```

如果规则安装后别名没有立即出现，拔插一次 USB 摄像头再检查。规则绑定的是序列号和视频接口，不依赖易变化的 `/dev/videoN` 编号。

功能包中提供了已验证设备的规则文件：

```text
/home/ubuntu/ros2_ws/src/Camera_USB_and_CSI/udev/99-usb-camera.rules
```

## 5. 导入到其他 ROS 2 工作空间

将整个 `Camera_USB_and_CSI` 目录复制到目标工作空间的 `src` 下。例如：

```bash
cp -a Camera_USB_and_CSI /home/ubuntu/ros2_ws/src/
```

每台目标主机都应重新运行绑定脚本，让脚本读取 USB 摄像头的 VID、PID、序列号和
V4L2 接口索引，不要直接复用其他设备的静态规则。

## 6. 编译功能包

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select camera_usb_and_csi
source /home/ubuntu/ros2_ws/install/setup.bash
```

确认 ROS 2 已发现包和可执行节点：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 pkg prefix camera_usb_and_csi
ros2 pkg executables camera_usb_and_csi
```

## 7. 启动 CSI 相机

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 launch camera_usb_and_csi camera.launch.py camera_type:=CSI
```

常用 CSI 参数：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 launch camera_usb_and_csi camera.launch.py \
  camera_type:=CSI \
  csi_sensor_id:=0 \
  csi_capture_width:=1280 \
  csi_capture_height:=720 \
  csi_output_width:=640 \
  csi_output_height:=480 \
  csi_framerate:=60 \
  csi_flip_method:=0 \
  image_topic:=/image_raw
```

`csi_flip_method` 可取 `0` 到 `7`，用于旋转或翻转画面。

## 8. 启动 USB 相机

推荐使用固定别名：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 launch camera_usb_and_csi camera.launch.py \
  camera_type:=USB \
  usb_device:=/dev/usb_cam
```

USB 默认参数为 `640x480 @ 30 FPS`、`MJPEG`，适合在 rqt 中实时查看。需要更高分辨率时可通过下面的参数修改。

修改 USB 端口、分辨率和格式：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 launch camera_usb_and_csi camera.launch.py \
  camera_type:=USB \
  usb_device:=/dev/video1 \
  usb_width:=640 \
  usb_height:=480 \
  usb_framerate:=30 \
  usb_pixel_format:=MJPEG \
  image_topic:=/image_raw
```

对于同时支持 `MJPEG` 和 `YUY2` 的 USB 摄像头，推荐使用 `MJPEG`，其 USB 带宽占用更低。

## 9. 检查 `/image_raw`

启动任一相机节点后，在新终端执行：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 topic info /image_raw --verbose
ros2 topic hz /image_raw
```

消息类型应为：

```text
sensor_msgs/msg/Image
```

## 10. 使用 rqt_image_view 查看画面

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 run rqt_image_view rqt_image_view
```

在左上角话题下拉框中选择：

```text
/image_raw
```

发布端使用传感器数据 QoS（Best Effort），适合实时图像，掉帧时不会积压旧画面。

## 12. 与 collect_picture 配合

`collect_picture` 和本相机包都默认使用 `/image_raw`，无需额外指定环境变量。先启动 CSI 或 USB 相机：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 launch camera_usb_and_csi camera.launch.py camera_type:=CSI
```

然后在另一个终端启动采集软件：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

/home/ubuntu/Software/collect_picture/run_collect_picture.sh
```

软件会直接订阅 `/image_raw`。只启动一个相机发布节点，避免 CSI 和 USB 同时向该话题发布图像。

## 13. 常见问题

### CSI 的 GStreamer 管线打不开

检查 OpenCV：

```bash
python3 -c 'import cv2; print(cv2.__version__, cv2.__file__)'
```

用户目录的 OpenCV 4.11 没有 GStreamer 支持。本包会主动移除用户 site-packages，使用 `/usr/lib/python3/dist-packages` 中的系统 OpenCV。

如果出现 `cannot allocate memory in static TLS block`，可临时执行：

```bash
export LD_PRELOAD=/lib/aarch64-linux-gnu/libGLdispatch.so.0
```

### `/dev/usb_cam` 不存在

重新运行绑定脚本，或拔插 USB 摄像头：

```bash
bash /home/ubuntu/ros2_ws/src/Camera_USB_and_CSI/scripts/install_usb_camera_rule.sh \
  --device /dev/video1
```

### USB 管线打不开

确认没有其他程序占用摄像头：

```bash
fuser /dev/usb_cam
```

也可以绕过别名测试原始端口：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 launch camera_usb_and_csi camera.launch.py \
  camera_type:=USB usb_device:=/dev/video1
```

### rqt_image_view 看不到话题

确认相机节点终端没有报错，然后检查：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 node list
ros2 topic list
ros2 topic info /image_raw --verbose
```

确保启动节点和 rqt 的终端都加载了同一个 ROS 2 环境，并且 `ROS_DOMAIN_ID` 一致。

如果节点正在运行，但普通 `ros2 topic list` 显示缓存结果，重启 ROS 2 CLI daemon，或使用不经过 daemon 的查询：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 daemon stop
ros2 daemon start
ros2 topic list --no-daemon
ros2 topic info /image_raw --verbose --no-daemon
```
